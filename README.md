# flor-platform-docs

Экосистемный уровень документации Flōr Group: нормативные стандарты, процедуры
работы с документацией и опорный шаблон проекта. Описывает связи между продуктами
и общие правила — то, что не принадлежит ни одному продукту в отдельности.

## Кому и зачем

- **Человеку** — начать отсюда: карта ниже говорит, где что лежит.
- **Агенту** — точка входа `CLAUDE.md`: маршрутизатор задач и семь всегда
  действующих правил. Агент не читает репозиторий целиком — только разделы,
  на которые указал маршрутизатор.

## Как подключить

Репозиторий подключается в любую сессию, где идёт разработка или оформление
документации любого продукта экосистемы, — рядом с репозиторием продукта.
Агент получает `CLAUDE.md` автоматически; человеку достаточно этой страницы.

## Карта

| Путь | Что там |
|---|---|
| `CLAUDE.md` | Маршрутизатор для агента: что читать под задачу, правила П-1…П-7 |
| `standards/` | Нормативное: что проект **обязан** делать. Главный документ — `ARCHITECTURE-STANDARD.ru.md` (FLOR-ADS), парная английская версия рядом |
| `guides/` | Процедурное: **как** делать — уровни документации, спецификации, гейты |
| `golden-path/` | Опорный шаблон проекта: скелет, конвейер, валидатор |
| `decisions/` | Экосистемные решения (затрагивают более одного продукта) |
| `MISSING.md` | Реестр незаведённого: чего ещё нет, почему и при каком условии появится |

Раздела нет ни в карте, ни в репозитории — смотри `MISSING.md`: отсутствие
раздела там объяснено и не является разрешением действовать по своему усмотрению.

## Правила, которые стоит знать до чтения

Нормативные документы (`standards/`) изменяются только через экосистемное решение
в `decisions/`; процедурные (`guides/`) правятся свободно, но не противоречат
нормативным. При конфликте проектного документа с экосистемным побеждает
экосистемный. Полный свод — в `CLAUDE.md`.

Язык репозитория — русский; исключение — английская версия стандарта.
